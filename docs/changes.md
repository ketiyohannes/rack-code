## 2026-10-28 — Reliable native Electron checks: the flaky message-queue check (merged in v0.0.1)

`npm run test:message-queue` failed once with no output and then passed; `test:orchestra` showed the same pattern earlier. Both causes were in the checks, not the app. A shared harness now makes every failure print its reason.

- **Most likely cause: the check window stopped updating when another app covered it.** Rack applies state on animation frames (`packages/ui/src/store.ts`). Chromium stops those frames for a window that macOS reports as covered by another app's window, so the DOM froze while the host kept going, and the next wait timed out after 15 s. Reproduced on demand by opening a full-screen window from a second Electron process 1.2 s into the run: the untouched original check failed 2 of 2 times ("UI condition timed out: document.querySelector('.message-queue').hidden"). The new failure report shows the state directly ("page: hidden … no animation frame within 1s; window visible: true"). Fix: `fixture-harness.ts` turns on Chromium's test-only switches `disable-backgrounding-occluded-windows`, `disable-renderer-backgrounding` and `disable-background-timer-throttling`, the same ones Puppeteer passes by default, for the check process only. With them, covered runs passed 13 of 13 across three batches. The shipped app is unchanged.
- **Why it was silent.** Each check printed with `console.error` and then called `app.exit()` straight away, which can drop output when stdout and stderr are pipes. Electron also reports page exceptions only as "Script failed to execute". Every exit now goes through `finish()`, which waits for both streams to drain.
- **Secondary race, fixed in the check.** After the host starts a queued message by itself (auto-advance, Send now, Resume, an edit's resend), the runtime can reach its gate before the window receives `run.started`. Until then the composer still shows "Run", and steps 7 and 8 read `document.querySelector('button[aria-label="Queue message"]').disabled` with no null guard. The check now waits for that turn to show as running with Stop available (`waitForRunning`), and its waits are null-safe. This could not be reproduced faithfully: the window is only the host's own time between settling one run and starting the next. An event-only delay reproduced it, but that delay also let command replies overtake events, which Electron's IPC and the daemon WebSocket never do. `RACK_CHECK_EVENT_DELAY_MS` therefore delays events and replies by the same amount, keeping their order.
- **Reloads now wait for the new page.** `webContents.reload()` returns immediately, so the condition after each reload ran on the old page, where it was already true. `reloadAndWait()` waits for `did-finish-load` and a marker that only the old document carries. This strengthens the reload assertions in the message-queue, orchestration, tool-group and run-changes checks; no assertion text changed.
- **Shared harness (`apps/desktop/scripts/fixture-harness.ts`).** Named steps. `js()` keeps the page's own exception and stack. `until()` reports the last result or error on timeout. The watchdog stays armed through cleanup, and cleanup errors are reported in addition to the original error, never instead of it. Renderer crashes, hangs, preload errors, child-process crashes and unhandled rejections fail the check with a reason. Failure reports include console errors, page visibility and animation-frame state, check-specific diagnostics and a screenshot (`/tmp/rack-<check>-failure.png`). The message-queue check adds the requests the runtime received, open gates, the queue, the turns, the composer buttons, the prompt, the focused element and any alerts. Overrides for proving failure paths: `RACK_CHECK_WATCHDOG_MS`, `RACK_CHECK_UNTIL_MS`, `RACK_CHECK_EVENT_DELAY_MS`. The message-queue, orchestration, tool-group and run-changes checks use the whole harness; desktop-features uses only `finish()`. Time limits are unchanged (15 s per wait, 90 s overall for the message-queue check).
- **Validation performed.** Exit codes were read directly, with no `| tail`. `test:message-queue`: 20 of 20 consecutive passes, 5 of 5 with `RACK_CHECK_EVENT_DELAY_MS=150`, 5 of 5 with the window covered, 10 of 10 while `npm test` ran alongside (runs took 5–12 s instead of 3–4 s), and 10 of 10 through a pipe with the PASS line present. Deliberate breaks each printed the step and reason and exited 1: a false assertion, `RACK_CHECK_UNTIL_MS=1`, `RACK_CHECK_WATCHDOG_MS=2000` (also through a pipe), and `forcefullyCrashRenderer()`. `test:orchestra` passed 5 of 5 in a row; `test:tool-groups`, `test:run-changes` and `test:desktop-features` pass. Typecheck and boundaries are clean, and the full suite passed (563 of 563).

Windows and Linux, where occlusion handling differs. `scripts/` is outside the project typecheck; checked with a temporary config, it shows one existing error: `verify-desktop-features.ts` calls `host.shutdown()` without its timeout argument.

## 2026-10-25 — A Timeline capture could miss an edit (branch `build/github-release`)

The flaky CI test reported in the previous entry was a real defect in Timeline's capture, not a slow machine.

- **The bug.** `GitSnapshotRepository.capture` reuses the private index it built for a repository, restoring the bytes into a fresh temporary file. Git only distrusts an index entry whose timestamp is not older than the index's own, so dating the restored index to *now* switched off the protection against a file that changed in the same moment the index was written. A file edited within the same second as the previous capture that also kept its size was read from stale stat data: identical tree, `capture` answered `unchanged`, and the edit was never recorded. On Git builds without nanosecond stat support — most Linux distributions — that window is a whole second. Apple's Git has nanosecond stat, which is why macOS never reproduced it.
- **The fix.** The cache keeps the index file's modification time alongside the bytes and restores it with `utimes`, so the comparison the bytes were written for still applies. The steady-state cost is unchanged: the claimed time advances with every capture, so only files touched since the last one are re-read.
- **How it was found.** Three hypotheses were tested and discarded on evidence, not argument: CPU contention (it failed at a 30s deadline), a missing Git identity (the Timeline writer sets `GIT_AUTHOR_*`/`GIT_COMMITTER_*` itself), and Git's stat cache missing a same-size rewrite in general (a Linux runner detects that). Instrumenting the capture path on a Linux runner showed both captures running to completion while the ref never moved, and the snapshot in the history carried a `createdAt` of `.000Z` — second granularity — which pointed at the index's stat comparison.
- **Regression test.** `performance.test.ts` pins a file's modification time so the race is deterministic on either kind of Git build. Verified in both directions: it fails against the unfixed code and passes against the fixed code.
- **Validation.** Full suite green at 508 tests. Not done: the Electron fixtures and packaging were not re-run for this change, and the fix has not yet been observed over repeated runs on a Linux runner.

## 2026-10-25 — A Git fixture that depended on the machine's identity (branch `build/github-release`)

The first CI run failed one test on Linux that passes on a developer's Mac, which is the kind of thing CI exists to find.

- **`packages/node-adapters/src/git/git-changes.test.ts`.** `git merge` resolves the committer identity *before* it attempts the merge, so on a machine with none it exits 128 with a clean tree rather than conflicting. The fixture's commits supplied an identity inline but the merge did not, and `assert.rejects(git("merge", ...))` accepted that failure as the expected one. The snapshot then described a clean repository and the row assertion failed with no indication why. GitHub's Linux runners have no configured identity and a host name that yields an empty one, which is why only they saw it.
- **Fix.** The repository is configured with an identity right after `git init`, the way the other fixtures that merge already do (`git-source-control.test.ts`, `timeline-service.test.ts`), and the rejection now has to be a conflict: any other Git error fails the test where it happens instead of being reported three assertions later.
- **An open, unrelated flake.** `timeline-service.test.ts:53` ("container projects discover their single repository...") fails intermittently on GitHub's Linux runners, roughly half the time, waiting for the checkpoint that should follow a watcher notification. The same commit passed on one branch and failed on the other, twice. A first attempt blamed CPU contention and raised the wait from 10s to 30s; it failed again at 30s, which disproves that reading — a condition that needs milliseconds and is still unmet after half a minute is never going to be met, so this is a race, not slowness. That change was reverted rather than left standing on a wrong diagnosis. The cause is not yet found, it predates this work, and it reproduces on neither macOS nor a Linux run that happens to win the race. It matters because the release workflow's `verify` stage runs the full suite, so a tagged release will fail about half the time until it is fixed.
- **Validation.** Reproduced locally by denying git any ambient identity (`GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` plus `user.useConfigOnly=true`), which failed exactly that one test and no other, matching CI. Both environments pass after the fix, and the workspace typechecks. No production code changed: the reader was never at fault.

## 2026-10-25 — Tagged releases (branch `build/github-release`)

The repository had no CI and no way to produce a downloadable build. It has both now.

- **`.github/workflows/release.yml`.** A `v*` tag (or a manual dispatch naming one) runs three stages: **verify** on Linux, which refuses a tag that disagrees with the version in `apps/desktop/package.json` and then runs typecheck, boundaries, the full suite and the web build; **package**, a `fail-fast: false` matrix over macOS Apple silicon, macOS Intel, Windows x64 and Linux x64; **publish**, which attaches every archive to a draft release built from `.github/release-notes.md` plus generated notes.
- **One runner per platform, because nothing cross-compiles.** The Codex runtime and the Claude Agent SDK ship as optional per-platform npm packages, `node-pty` compiles on install, and `@electron/packager` packages the machine it runs on. Adding an ARM Windows or Linux target is a matrix entry and nothing else.
- **`electron-rebuild` is not part of packaging.** `node-pty` 1.1 is an N-API addon, so the binary `npm ci` builds loads under both Node and Electron; the Electron PTY fixture exercises that directly. The root `rebuild:native` script stays for the cases that need it.
- **`apps/desktop/scripts/archive-release.ts`** and `npm run archive:desktop`. Wraps the packaged directory in one file per platform with the system archiver, so the pipeline gains no dependency. macOS uses `ditto -c -k --sequesterRsrc --keepParent` rather than `zip`, which does not preserve the symlinks inside an Electron framework or the bundle's signature; Linux uses `tar.gz` to keep the executable bit. Names are `Rack-<version>-<macos|windows|linux>-<arch>`, since a file name is read by whoever is choosing a download.
- **The release is a draft.** The builds are unsigned, so the notes carry the `xattr -dr com.apple.quarantine` step, the SmartScreen path, the fact that Codex ships inside the app while connecting a Claude account still needs the Claude Code CLI on `PATH`, and where records live. Publishing stays a decision rather than a side effect of pushing a tag.
- **`.github/workflows/ci.yml`.** Typecheck, boundaries, tests and both builds on pushes to `main`/`dev` and on pull requests, with in-progress runs cancelled on a new push.
- **Validation.** The macOS Apple silicon path was exercised end to end on this machine: package, archive, and expansion of the resulting 381 MB zip back into a bundle that passes `codesign --verify --deep --strict` and whose bundled Codex runtime reports `codex-cli 0.163.0`. Both workflows parse as YAML; the tag-versus-manifest check was run against a matching and a mismatching tag. The archive step's two upload globs are correct: `upload-artifact` fails only when no pattern matches anything.

No release has been cut. ## 2026-10-23 — Remote transports, daemon, and the remaining apps (branch `refactor/monorepo-workspaces`)

Completes the monorepo migration: every declared app and package now contains working code instead of a placeholder README.

- **Remote protocol** (`packages/contracts/src/protocol.ts`). `hello`/`welcome` carrying `PROTOCOL_VERSION`, request/response by ID, sequenced events, ping/pong, and typed handshake rejections (`unsupported_protocol`, `unauthorized`, `malformed_handshake`). Controllers and daemons update on different schedules, so a version mismatch is refused at the handshake rather than failing later on an unknown field.
- **Transports in `@rack/host`** (`packages/host/src/transport/`). `UtilityPortTransport` serves the Electron utility process (and carries the browser round-trip to main); `RemoteHostServer` serves remote controllers over a four-method `HostConnection` interface, so no socket library enters `@rack/host` and the handshake, authorization and replay rules are unit-tested with fakes. `EventStream` sequences events and keeps a bounded replay tail. `startHost` is the shared startup sequence: compose, run `execution.initialize()` to completion before serving any command, then start Timeline tracking in the background. `apps/desktop/src/host/entry.ts` is now Electron glue only, and no longer calls `initialize()` twice.
- **Resumable sessions.** A controller checkpoints the highest event sequence it applied and resumes from it. A buffered gap is replayed; an evicted gap, or a cursor from a previous daemon process (detected via `instanceId`), answers `truncated` and the controller re-reads state. Correct in all cases because host events are a freshness signal, not the source of truth.
- **Delivery guarantees.** Commands that never reached a socket are queued and sent on the next `welcome`; commands that *were* sent and then lost their connection fail with `host_unavailable` rather than being retried, because the daemon may have executed them and replaying `projects.add` would duplicate state. Safe resending needs idempotency keys, which the protocol does not have.
- **`apps/daemon`** (`@rack/daemon`). `rack-daemon` runs the same `HostApi` headless over WebSocket at `/rack`, with an unauthenticated `/health` probe for VM supervisors. Binds loopback by default; `--host` warns. Authentication is a 256-bit pairing token, stored `0600`, compared in constant time, never logged, overridable by `RACK_DAEMON_TOKEN` for VMs. Bounded shutdown on SIGINT/SIGTERM. Composed without a browser driver, so browser commands answer `feature_unavailable`.
- **`@rack/client` transports.** `ClientTransport` with an optional `shell`, so desktop-only operations (folder pickers, open-in-editor, shared browser) raise `feature_unavailable` on a remote connection instead of failing unpredictably. `createWebSocketTransport` handles reconnection with jittered backoff, resume, heartbeats, and fatal-vs-retryable failures. `createHostClient()` keeps its existing no-argument call site.
- **`@rack/ui` is transport-agnostic.** The interface moved to `mountApp({ root, host, params })` in `mount.ts`; `app.ts` is now just the desktop bootstrap. The Windows/Linux menu strip is gated on `host.hasShell` so a browser never renders a dead menu bar.
- **`apps/web`** (`@rack/web`). The same interface in a browser: pairing screen, connection banner, esbuild bundle, development static server. The pairing token lives in `sessionStorage` by default with opt-in `localStorage`; plaintext `ws://` is refused to anything but loopback; the page keeps the strict CSP with `connect-src ws: wss:` added, since the daemon address is chosen at pairing time. Refused and unreachable failures are handled differently so a reboot does not discard a valid token.
- **`apps/mobile`** (`@rack/mobile`). Capacitor shell staging the web bundle into `www/` (source maps stripped), `androidScheme: https` for a secure context, cleartext off. `ios/` and `android/` are generated by `npx cap add` and are not committed. The layout is still the desktop one; a phone-specific interface is not written.
- **`apps/vm-manager`** (`@rack/vm-manager`). microVM lifecycle from outside the VMs: a pure transition table, transient states applied under a write lock so concurrent requests get 409 rather than racing, driver errors settling `failed` with a reason instead of a guessed state, and restart reconciliation. A working file-backed `local` driver (declaring `simulated: true`) makes safe-shot rollback actually testable; the Firecracker/Cloud Hypervisor seam throws 501 and documents what an implementation must do.
- **`apps/cloud`** (`@rack/cloud`). Accounts (scrypt hashes, SHA-256 token digests, identical answers for unknown address and wrong password), subscriptions, a relay registry with heartbeat-derived liveness, and HMAC-signed single-use relay tickets. Provisioning records an assignment before calling vm-manager so a timeout leaves evidence rather than a silent leak. The Stripe seam throws 501; the manual billing provider states everywhere that it takes no payment.
- **`native/tsnet-sidecar`.** Go module joining a tailnet with `tsnet` and reverse-proxying to the local daemon, including WebSocket upgrades (`ForceAttemptHTTP2: false`, no `ReadTimeout`/`WriteTimeout`, `FlushInterval: -1`). The auth key is environment-only, redacted in every log path, and scrubbed from library output. Refuses to start rather than waiting on interactive login.
- **`infra/images`.** Dockerfile-based guest rootfs plus a documented ext4 conversion that needs no host root or loop devices. systemd units for the daemon and sidecar (separate users, so agent code cannot read the tailnet key), a boot preflight that fails the boot on a missing data disk or world-readable token, and a documented three-disk contract. Image-owned paths are passed as `ExecStart` arguments, which a config disk cannot rewrite.
- **Build outputs.** Stale root `dist/`, `dist-desktop/` and `release/` (≈1 GB) were deleted; they predate the workspace move and nothing referenced them. `.gitignore` now documents each output location (`apps/desktop/dist`, `apps/desktop/release`, `apps/web/dist`, `apps/mobile/www`, generated Capacitor platforms, the Go binary). Every build writes inside its own workspace.
- **Boundaries and scripts.** `check-boundaries.ts` gained rules for the five new apps (`daemon`: contracts + host; `web`: client + contracts + ui; `mobile`, `vm-manager`, `cloud`: nothing) and skips `www/`. Root scripts added: `start:daemon`, `start:web`, `build:web`, `build:mobile`, `daemon:token`.
- **Validation.** Typecheck clean in all 14 workspaces; boundary check passes; the full suite passes (496 tests, up from 389 — 107 new). The desktop build produces the same externals as before and `ws` does not enter its bundles; the run-changes, desktop-features and orchestra Electron fixtures pass; macOS ARM packaging passes and ships the same module payload (the empty scoped directories the packager leaves behind are pre-existing and carry no bytes). The daemon was smoke-tested against a real composed application: pairing, concurrent command dispatch, `/health`, and graceful SIGTERM shutdown. `apps/cloud` and `apps/vm-manager` were smoke-tested against each other over HTTP end to end. Go `vet`/`build`/`test`/`test -race` pass.
- **Not done.** No VM was booted and `docker build` was never run (no Docker daemon here), so the image is unverified beyond shell syntax and asserted contents. No real hypervisor, payment provider, email, or tailnet was exercised. End-to-end encryption, so a relay sees only opaque blobs, is not implemented. `contracts` still depends on core and features. `apps/desktop/scripts` remain untypechecked (pre-existing). The mobile interface is still the desktop layout, and no QR pairing exists.
