# Changes panel

The right-hand Changes surface uses a compact Source Control layout, following the file/status and comparison conventions in [VS Code's Source Control view](https://code.visualstudio.com/docs/sourcecontrol/overview). Repository headers show the folder and current branch. Collapsible Staged Changes, Changes, and Merge Changes sections show file counts, filenames, parent folders, and status letters (M/A/D/R/C/U/T/!). A partially staged file appears in both staged and working-tree lists with different comparisons.

Click a file to open its diff below the list. Staged entries compare HEAD with the index; Changes entries compare the index with the working tree. Untracked text is displayed as a new file. Merge Changes compare the current branch's conflict stage with the working file and remain marked as unresolved. The viewer has old/new line numbers, addition/deletion backgrounds, hunk headings, and an inline/split toggle. In split mode, each half has its own horizontal viewport and both follow the same vertical position. Open file uses the desktop's existing safe open/reveal behavior; deleted files keep the diff but disable opening a missing file. Close diff returns to the file list.

Selection, section expansion, and diff scroll positions survive refreshed snapshots. Switching projects clears the previous project's selections. Multiple detected repositories can be selected individually or viewed together; refresh and the repository-options menu keep discovery controls available without filling the panel with setup text. Reads start at a two-second interval while visible and back off to ten seconds when unchanged. Changed results reset the interval; manual refresh and project/run transitions remain immediate. Hidden windows skip polling and refresh on return. Stale replies cannot cross projects or repository selections.

## Ownership and bounds

Projects owns the read-only `ProjectChanges` contract. Its optional `branch` and `files` fields contain application-owned `ProjectChangeFile` records with a scoped path, status, group, per-file patch, optional previous path, and preview notice. The existing combined `diff` remains available for older clients. The Git adapter interprets [NUL-delimited porcelain status](https://git-scm.com/docs/git-status#_porcelain_format_version_1); the renderer never parses native XY status codes. This preserves changes that cancel in a HEAD-versus-working-tree comparison, including a staged edit reverted locally.

Status filenames are decoded without newline/space splitting, and tracked patches use paths relative to the selected folder. Batch patch indexing avoids running one Git process per file. Status rows are limited to 500 per repository; previews of new files are limited to 50 files and 128 KB each. Per-file previews share a 1-million-character budget, and the legacy combined patch is separately capped at that size. Binary/special files and unavailable or shortened previews show notices. Commands retain five-second timeouts and a 2 MB output limit.

The panel consumes Git state without staging, discarding, committing or switching branches. `GIT_OPTIONAL_LOCKS=0`, disabled external diff drivers, and disabled text conversion keep background reads from rewriting the Git index or invoking diff conversions. The workbench owns discovery/polling and view memory; `features/changes-view.ts` owns file/diff rendering, and `change-diff.ts` owns numbered-row/split alignment.
